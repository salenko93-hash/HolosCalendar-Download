# Локальний український голос — 4.1.0

Це перший етап: готова багатомовна Whisper виконується на телефоні й передає текст у наявний український парсер. Власного донавчання ваг або збирання голосів для навчання ще немає.

## На телефоні

1. Відкрийте форму події. «Голос: на цьому телефоні» — початковий режим.
2. Натисніть голосове введення → «Завантажити модель у браузері». Почніть із Tiny (близько 75 МіБ); Base (близько 142 МіБ) потребує більше пам’яті й обчислень. Модель можна завантажити на ПК скриптом DOWNLOAD_MODEL.ps1 і перенести на телефон.
3. Поверніться та натисніть «Вибрати файл моделі». Потрібна багатомовна `.bin`, а не `.en`. Під час імпорту перевіряється повний вміст; пошкоджений чи інший файл не замінює чинну модель.
4. Натисніть «Почати запис» і дозвольте мікрофон. Після появи «Слухаємо українською» скажіть одну команду, потім «Завершити запис». Межа — 30 секунд.
5. Дочекайтеся тексту у формі. Перевірте назву, дату, час та решту полів і збережіть подію. Розпізнавання не зберігає подію автоматично.

Після імпорту локальний режим працює без мережі. Запис перебуває тільки в RAM; він не зберігається в аудіофайл і не завантажується на сервер. Дозвіл INTERNET у застосунку не додано. Браузер та постачальник файлів можуть використовувати мережу для одноразового завантаження. Системний режим Android є окремим явним вибором і може передавати голос своєму постачальнику; автоматичного переходу до нього немає.

Згортання, вихід або поворот екрана локального голосу скасовує запис/обробку. Подія в редакторі залишається. Під час розпізнавання працює фоновий worker; екран має кнопку повернення й не вимикається автоматично до завершення операції. Для обчислення задано таймаут дві хвилини, який перевіряється між операціями рушія. Вихід із застосунку все одно скасовує її. «Прибрати модель» видаляє тільки ваги, а не календарні події.

## Сумісність і якість

4.1.0 збирається для arm64-v8a (телефон) і x86_64 (емулятор), Android 8.0+. Підтримки 32-бітних ARM у цьому APK немає. Це CPU-розпізнавання; час, пам’ять, нагрів і якість на Redmi потрібно виміряти. Tiny/Base підтримують українську, але не гарантують правильного розуміння кожної фрази. Підтвердження полів залишається обов’язковою частиною роботи.

За відсутності пам’яті спробуйте Tiny та коротшу команду. Якщо не чути мовлення, перевірте дозвіл, системний перемикач мікрофона, відстань та інші програми, що записують звук. Завжди доступні текстове введення й системний режим.

## Реалізація

- whisper.cpp v1.9.5, commit `d1be6fde11ac6e0407606b4e42fe72d34add8037`, MIT. Потрібний код включено в third_party/whisper.cpp, без завантаження C++-залежностей під час CMake.
- NDK 27.2.12479018, CMake 3.22.1, C++17, CPU, до чотирьох потоків, GPU/OpenMP/KleidiAI/мережеві модулі вимкнені. Debug-рушій теж оптимізований. ELF і пакування перевіряються на вирівнювання 16 КіБ.
- AudioRecord: mono PCM16, 16 кГц, не більше 480000 відліків. Короткий/тихий запис відхиляється до виконання моделі.
- Whisper: `language=uk`, `translate=false`, без історії попередніх команд, timestamps та друку тексту в журнал.
- Native context належить одній операції; скасування та закриття використовують shared ownership, щоб не звільняти тензори під час обчислення.
- SpeechModel: обмеження файла 160 МіБ, контентні SHA-1 із зафіксованого upstream; спочатку перевірка, потім атомарна заміна приватної копії. Це контентні pins, не цифровий підпис. Довільні локальні ваги не приймаються.

Приймаються офіційні Tiny `bd577a113a864445d4c299885e0cb97d4ba92b5f`, Base `465707469ff3a37a2b9b8d8f89f2f99de7299dac` та відтворювана конвертація Base `faccb500275cbab28076305880ce39de190f01c0`.

Остання отримана зі справжнього OpenAI `base.pt`, SHA-256 `ed3a0b6b1c0edf879ad9b11b1af5a0e6ab5db9205f891f668f8b0e6c6326e34e`, конвертером із вказаного whisper.cpp. Для локальної перевірки першоджерело було відновлене з публічної дзеркальної копії й звірене з SHA-256 у OpenAI whisper/__init__.py до читання PyTorch checkpoint. Довіряємо перевіреному вмісту, а не назві дзеркала. Сховище Hugging Face недоступне з цього хмарного середовища. Рекомендований шлях користувача — офіційні Tiny/Base за посиланнями в models/README.md.

## Перевірки

OfflineAudioTest перевіряє межі PCM, тишу, довжину, підтримувані/непідтримувані моделі, пошкоджений/завеликий файл, скасування та збереження попередньої моделі. OfflineSpeechFlowTest перевіряє вибір локального екрана, повернення українського тексту в парсер, відсутню тривалість, скасування, наддовгий результат, відмову імпорту й справжнє завантаження JNI.

Окремий OfflineModelDeviceTest у `app/src/offlineDeviceTest` включається лише через `-PofflineDeviceCheck`. Йому потрібні файли у приватній папці застосунку `files/speech-test/`: `ggml-base.bin` та `uk-natural.wav` (mono PCM16 16 кГц, до 30 с). Відсутні файли є помилкою, а не тихим пропуском тесту. Він перевіряє справжній імпорт і CPU-розпізнавання українського аудіо. Стандартний CI не потребує великих ваг.

```sh
./gradlew -PofflineDeviceCheck connectedDebugAndroidTest
```

Для тестового фрагмента використано перші 10 секунд публічного синтетичного українського зразка Piper mykyta/high: https://github.com/rhasspy/piper-samples/tree/master/samples/uk/uk_UA/mykyta/high. Модельний card посилається на український датасет Apache 2.0. Це перевірка проходження реального аудіо через модель, а не оцінка якості на різних людських голосах чи реальному мікрофоні. Зразок і ваги до проєкту не включені. На примітивнішому голосі eSpeak результат був слабким; це ще одна причина перевіряти поля й не вважати модель вже донавченою для календаря.

## Наступний етап

Після випробування на телефоні можна окремо збирати погоджені приклади помилок та точні розшифрування для донавчання ASR. Для моделі розуміння команд потрібна окрема розмітка полів. Наявні 87 мовних кейсів лишаються незалежною перевіркою; записів користувача для навчання ця версія не збирає.

### Результат локальної перевірки

Повний модельний прогін на програмному AVD без KVM зупинено після понад 35 хвилин обчислень без завершення. Це **не успішна Android-перевірка повної транскрипції** і не замір швидкості телефона. Цей додатковий opt-in тест збережено для фізичного пристрою або швидкого емулятора.

Справжній JNI з того самого C++-файла додатково перевіряється на Linux-хості з реальними вагами та українським WAV: український результат, примусове скасування та таймаут. Для відтворення потрібні JDK 17, CMake, C++-компілятор і окремі модель/аудіо:

```sh
bash tools/check_speech_host.sh /path/to/ggml-base.bin /path/to/uk-natural.wav
```

Хостова перевірка не підтверджує якість мікрофона або швидкість Redmi. Звичайний Android-набір містить 56 сценаріїв, зокрема завантаження справжньої JNI-бібліотеки й безпечну відмову для некоректних ваг; він не потребує великих ваг.

Для відтворення конвертації локального Base використано assets OpenAI Whisper з commit `86098128c0b4f24f0e2aa2994de830614b474227`, PyTorch 2.5.1+cpu та NumPy 2.3.5. Результат конвертації перевірено за наведеним вище SHA-1. Користувачу для початку достатньо офіційної багатомовної Tiny/Base; донавчання не потрібне.
